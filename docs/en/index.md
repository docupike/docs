# i-doit up documentation

This documentation explains how to install, use, and administer i-doit up.
It starts with what is new in the current release, then shows where to begin and how the guides are organized.

## What's new in i-doit up 3.3.0

- **Worlds and Islands** add specialized views to i-doit up.
  The first World and Island are about licenses, see [Worlds and Islands](user/worlds-and-islands.md) and [License World and License Island](user/license-world-and-island.md).
- **Flows** automate recurring tasks with triggers, conditions, and actions, see [Flows](user/flows.md).
- **Rights for the admin role**: the admin role receives all rights for Worlds and Islands automatically, see [Rights and permissions](admin/rights-and-permissions.md).
- **Add-ons** are installed and uninstalled in the add-on overview.
  Uninstalling deletes all data of the add-on, see [Add-ons](admin/addons.md).

For all changes of a release, see the [Version history](ref/version-history.md).

## How this documentation is organized

The tabs at the top group the pages by task:

- **Installation guide** describes how to install i-doit up.
- **User guide** explains the daily work: objects, classes, and locations, the Finder, reports, Worlds and Islands, documents, Flows, imports, and use cases.
- **Admin guide** collects everything that needs administrative rights: CMDB configuration, users and access, tenant and subscription, data, and integrations such as add-ons, MCP, and n8n.
- **Developer guide** describes how to build add-ons.
- **Technical reference** lists the system requirements and the version history.

Each page is self-contained.
Follow the *Further readings* list at the bottom of every page to jump to related topics.
